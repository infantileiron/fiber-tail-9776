# 棉渡再生 · 来料杂质长尾验收

棉渡再生质检组按干样重量复核每批回收纤维，留存超标样、尾部截取和收料决定。

## 收料时怎么用

棉渡再生是一间模拟再生纤维分拣厂，收料组 6 人，日常跨两个班次。分拣站随车附供货批号和磅单。收料员从前、中、后舱分层取样，烘干后称总重，拣出纸屑、塑片和砂粒再称杂质重。手记转抄到 `来料抽样-1121.xlsx` 时容易出现三类问题。

1. 电子表格直接平均每份样的杂质率，干样 250 g 与 1,000 g 的贡献被算成一样。
2. 班组能看到平均值，拆不出是哪一袋高杂质样触发退货，也说不清尾部边界截取了多少克。
3. 改超标线时覆盖旧列，仓务拿到的验收结论无法对应原始称重和当时的阈值。

本应用从磅单和称重记录接手，到分批计算、复核和发布验收单为止。仓务按发布决定安排接收、复检隔离或退货，采购可用导出件同供货方沟通。台账中的决定标明历史发布版本，新增干样和诊断版本保留独立记录。

| 岗位 / 枚举 | 演示账号 | 演示口令 | 页面与权限 |
|---|---|---|---|
| 称重分析 · `analyst` | `analyst` | `cotton-scale` | 登记供货批号及干样，提交诊断，查看草稿结果和交接记录，导出验收单 |
| 收料复核 · `reviewer` | `reviewer` | `cotton-review` | 查阅批号、称重、草稿和交接记录，填写理由并发布收料决定，导出验收单 |
| 仓务观察 · `observer` | `observer` | `cotton-view` | 读取批号与称重，查阅和导出已发布验收单 |

## 计算与复核口径

- 单样杂质率 `x_i = m_i / w_i`，`m_i` 为杂质克数，`w_i` 为干样克数。全样加权均值 `sum(m_i) / W`，其中 `W = sum(w_i)`。
- 重量加权经验分布 `F(t) = sum(w_i × 1[x_i ≤ t]) / W`。相同杂质率合成一级阶梯。超标重量份额 `1 − F(t)` 严格按 `x_i > t` 计入。将超标线改到 7% 时，S-05 与阈值相等，超标份额降到 6.25%。
- 尾部份额为 `α` 时，按杂质率从高到低累计到 `αW` 克。边界样只取剩余配额，`尾部均值 = sum(取入克数 × 单样杂质率) / (αW)`。杂质率并列时按样号升序展示贡献，截取哪份并列样不影响均值。
- 指标严格超过对应上限时给出退货建议，两项都在上限内给出接收建议。复核岗可以发布接收、复检或退货，并须记录理由。结论发布后冻结。
- 诊断不足 3 份干样时保留失败版本和原因。零干重、杂质重高于干样重、超范围参数和重复样号会在写入时返回错误。
- 后端用有理数生成 ECDF、比较阈值和积分，报告输出可读数值，界面百分比显示两位小数。显式记录 `weighted-tail-v1`、四项参数、按样号排序的称重快照及其 SHA-256。同批新报告比较上一个成功版本，差额以百分点显示，快照有变时提示差额同时含样本影响。

## 启动

需要 Docker Compose。批次验收使用批次根目录的共享脚本。

```bash
cp .env.example .env
docker compose up --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

| 入口 | 地址 |
|---|---|
| 前端 | `http://127.0.0.1:18270` |
| FastAPI 文档与健康检查 | `http://127.0.0.1:19270/docs`、`http://127.0.0.1:19270/health` |
| PostgreSQL | `127.0.0.1:17770`，库与用户名均为 `fiber` |

| Compose 服务 | 技术与职责 |
|---|---|
| `frontend` | Nginx 1.27，托管原生 HTML/CSS/JS，反代 `/api/`，健康检查访问真实 API |
| `backend` | Python 3.11、FastAPI、psycopg，JWT 岗位权限、路由、输入校验、审计与 JSON 导出 |
| `worker` | Python 3.11，按 PostgreSQL 队列领取快照并计算，保存结果或业务失败，健康检查使用心跳 |
| `db` | PostgreSQL 16，持久化数据、作业状态、参数快照和发布决定 |
| `redis` | Redis 7，通知 worker 有新作业。暂时无法唤醒时 worker 轮询 PostgreSQL |

Compose 使用数据卷 `database`、`redis_data` 和 `work_state`。`work_state` 给后端、worker 共享运行心跳目录，验收单以数据库版本为准，导出时生成 JSON。批次网络子网为 `10.221.201.0/24`。`docker compose down` 保留卷，验收脚本使用 `down -v --remove-orphans` 清理本项目验收卷。

| 环境变量 | 用途 |
|---|---|
| `COMPOSE_PROJECT_NAME` | 容器和 Compose 项目短名，默认 `fiber-tail` |
| `FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` | 本机回环地址上的三个端口 |
| `NETWORK_SUBNET` | 本项目默认网络的 IPv4 子网 |
| `POSTGRES_PASSWORD`、`JWT_SECRET` | 本地数据库口令及 JWT 签名密钥 |
| `SEED_DEMO` | API 启动时初始化演示数据，默认 `true`。可手动重跑 seed |
| `PGHOST`、`PGPORT`、`PGDATABASE`、`PGUSER`、`PGPASSWORD`、`REDIS_URL` | Python 进程连接设置 |
| `WORKER_HEARTBEAT` | Worker 心跳文件，Compose 下默认 `/artifacts/worker.heartbeat` |

本地改动后可直接 `docker compose up --build --wait`。单独运行 Python 时，从 `backend/` 安装 `requirements.txt`，设置表中连接变量，分别通过 `python -m uvicorn src.app:app --port 8000` 与 `python -m src.worker` 启动进程。独立运行 worker 时可用 `WORKER_HEARTBEAT` 指向可写路径。联调前端使用 Compose 的 Nginx 入口以共用 `/api/` 代理。

## 源码与共享枚举

- `backend/migrations` 定义批号、抽检样、验收版本、发布决定与审计表。`src` 按路由、控制器、服务、模型、校验、配置和中间件分层。`scripts/seed_demo.py` 只插入未登记的种子自然键，同一批号由一次数据库事务补齐。
- `frontend/src` 将 API、会话状态、路由、页面、标签和工具拆分。批号条、版本历史、状态标签、表单错误提示复用于多个页面。
- 岗位 `reviewer / analyst / observer`、运行状态 `queued / succeeded / failed`、收料决定 `accept / retest / reject` 定义在 `backend/src/constants/domain.py`、`frontend/src/types/domain.js` 及迁移表的 CHECK 约束。前端 `constants/labels.js` 提供对应文案。
- 岗位用于登录、授权依赖、工作区及审计可见性，前端登录页、侧栏和岗位操作。运行状态用于队列、检查详情、导出和发布门禁，前端用于轮询、诊断回执和版本历史。收料决定用于算法建议、输入校验、版本发布、导出与台账，前端用于标签、复核表单和已发布决定。

## 已知限制

- 演示数据和阈值是模拟收料策略。干样测值描述抽样分布。是否可推广到整车取决于现场抽样覆盖和布点。
- 单项目本地部署，使用演示账号和 8 小时 JWT。外部部署需另外配置账号、签名密钥和 TLS。
- 仅支持整数克的逐份称重登记，单批最多 250 份。采用追加样号方式保留留痕，未提供批量导入、旧称重编辑和撤回发布。导出为带参数与快照的 UTF-8 JSON。
- 中文字形取决于本机字体。DM Sans 与 Newsreader 的拉丁子集随项目部署，可离线加载。
